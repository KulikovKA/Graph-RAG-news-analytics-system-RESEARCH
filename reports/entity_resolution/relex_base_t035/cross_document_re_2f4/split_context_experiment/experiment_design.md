# Stage 2F.4 — Split-Context ReLEx: frozen design

Дата клиента: 2026-11-13, Europe/Moscow. Исходный HEAD: `bacc41e`, ветка `design-v2-sequential-kg`, рабочее дерево перед работой чистое. Этот документ, диагностическая разметка и все контексты хешируются **до первого forward**. Изменять варианты, labels или пороги после просмотра scores запрещено.

## Вопрос и выборка

Сравнивается представление двух независимых исходных научных контекстов для фиксированной пары E2–E3. Только 28 ранее проверенных пар: P01–P06, N01–N12, W01–W10. Пары, выбранные native mentions, направления и canonical IDs сохраняются. E1/E4 могут помогать найти текст, но не становятся targets. Никаких новых документов, внешних определений, мостовых предложений или готовых ответов.

P — development candidates, не положительный gold. Предварительная консервативная разметка: P01/P04/P05 BACKGROUND-KNOWLEDGE DEPENDENT; P02/P06 HYPOTHETICAL TRANSFER; P03 TEXT-SUPPORTED SPLIT только в узком лексическом смысле «T cell activity имеет клеточного участника T cells». У P03 второй источник подтверждает совместимость класса, но participant-смысл уже читается из A. Поэтому **бесспорных положительных примеров, требующих объединить две независимые научные посылки, нет**. Все W/N — NEGATIVE / AMBIGUOUS относительно предложенного смысла; это не универсальный gold NO_RELATION. Изменение этой разметки по результатам модели не допускается.

P04 намеренно трактуется консервативно: overexpression/coexpression/expression в генном контексте совместимы, но формальное определение subtype в абстрактах не дано. P05 не описывает строение bundle. Разметка одного исследователя; альтернативная лексическая трактовка P04/P05 должна обсуждаться как чувствительность знаменателя, а не превращаться в новый gold.

## Общие входные правила

Модель видит только английские короткие entity/relation prompts существующей конфигурации и исходный текст с нейтральными `[DOCUMENT <native id>]` / `[END DOCUMENT <native id>]`. Для разрывов внутри одного документа используется `[PASSAGE BREAK]`. Границы и порядок A/B одинаковы во всех вариантах. Метаданные, scope, expected labels, ID пары, STRONG/PLAUSIBLE, комментарии аудитора и локальные relation labels модели не передаются. Только два fixed spans, по одному выбранному native mention на endpoint; повторные слова в тексте не становятся дополнительными target spans.

Исходные тексты, revision/source references, canonical/native IDs и native/joint offsets сохраняются. Полные абстракты обоих endpoints лежат в pair_scope_review.csv; точные использованные подстроки с source offsets — в contexts JSONL. Предложения выделяются фиксированной пунктуационной эвристикой, включая отсутствие пробела в OpenAlex; это не лингвистическая gold-сегментация. При crop ни один source character не переписывается.

## S1 — Minimal

По одному исходному предложению, содержащему выбранный target. Если предложение длиннее 96 GLiNER words, берётся непрерывное окно вокруг mention. Если два фрагмента с prompts превышают 512 subword tokens, граница сокращается по заранее заданной лестнице 96/64/40/20/0 words, сохраняя mention полностью. Для слов вне targets используется только source substring. Это короткий контекст, без искусственной связки.

## S2 — Extended

Если оба полных абстракта с prompts помещаются в 512 tokens, используются оба. Иначе из S1 непрерывно расширяется каждый документ: сначала ближайшими целыми предложениями; предпочтение источнику с меньшим количеством subword tokens, затем меньшей добавке, slot и source order. В остаток бюджета добавляются ближайшие полные GLiNER words тем же правилом. Балансировка не использует ожидаемое отношение или scores. Расширение заканчивается, когда ни одна ближайшая граница не помещается. Частичные крайние предложения и удалённые части явно видны по source offsets. Это воспроизводимый локальный выбор информативного окружения, а не доказанно оптимальный поиск evidence.

## S3 — Evidence-enriched

От S1 добавляются полные исходные предложения с native endpoints существующих incident RELEX_REL E2/E3. Это даёт соседей E1/E4, включая их контекст в том же документе. Приоритет: расстояние предложения от target, slot, source offsets, canonical triple ID. Никакие confidence или relation labels для выбора не используются. Дубли/пересечения сливаются; добавка, не помещающаяся в 512 tokens, пропускается. Сохраняются retrieval refs, статусы added/already_present/excluded_budget. Evidence windows полного абстракта сами по себе не становятся основанием добавить весь текст: используется локализация endpoint в исходном предложении. Если incident claims нет, S3=S1; выдуманного enrichment нет.

S3 — выборочное обогащение S1 научной окрестностью, S2 — максимальное непрерывное окружение; различаются объём и отбор исходного контекста. Они не являются контролируемым тестом одного только расстояния или длины. Если все S3 идентичны S2, отдельные S3-файлы и inference не создаются. При частичных совпадениях контекстов сохраняется явная pair-level эквивалентность, а ранее сохранённый полный вектор переиспользуется без forward. Аналогично исключаются повторы S3=S1 и S2=S1. Глобальные файлы S3 сохраняются только при отличии от S2.

## Фиксированный inference и техническая проверка

`knowledgator/gliner-relex-base-v1.0`, существующий локальный checkpoint и `build_relex_graphs.predict_window()`, веса и adapter не меняются. Онтология D берётся побайтно из ontology_experiment/cross_document_ontology.json: SUBTYPE_OF, STAGE_OF, PART_OF, HAS_PARTICIPANT, HAS_PROPERTY, USED_FOR, APPLIED_TO, POTENTIALLY_APPLICABLE_TO, DERIVED_FROM. Порядок labels и английские prompts неизменны. CPU, прежние 2 threads, seed 0, deterministic algorithms, eval/torch.inference_mode, offline. Фактические runtime versions и hashes сохраняются.

До inference проверяются source/joint offsets, word alignment, count с truncation=False, реальный collator и index-to-label mapping для каждого входа. Во время inference проверяются 2 spans, 2 directed pairs, все 9 prompts, отсутствие word truncation в существующем adapter, ровно 18 уникальных sigmoid scores. Порог adapter -1 сохраняет даже точный sigmoid zero; это только cutoff сериализации, не положительный порог. Полные векторы содержат все направления/labels, включая <0.35. Это некалиброванные scores, не вероятности научной истинности.

Один forward на уникальный фактический вход пары. Checkpoint fsync после каждой пары, input hash/signature и duplicate checks при resume. Hashes всех ранее отслеживаемых файлов, исходных артефактов, checkpoint, runner и adapter контролируются до/после. Для длительных операций — настоящее tqdm и заметное сообщение КАПСОМ. Предыдущий intra-document sanity/adapter compatibility используется как имеющееся свидетельство; новый intra-document опыт не запускается.

## Анализ и аудит

Пороги заранее: >=0.35, 0.40, 0.45, 0.50, 0.55, 0.60, 0.65, 0.70, 0.75, 0.80, 0.85, 0.90. Только фильтрация сохранённых scores, forwards для thresholds=0. Для P01–P06: expected code и direction из прежнего D-coverage, score и обратный score, maximum, delta S2−S1/S3−S1, exact hit и смысл/ограничения. P05 ожидается E3→E2 PART_OF. P02/P06 не превращаются в actual application.

Каждый выход >=0.35 проходит содержательный source-based аудит: SUPPORTED_CONCEPT_RELATION, PLAUSIBLE_HYPOTHESIS, UNCERTAIN, REJECTED. Проверяются type, head/tail, совместимость объектов, concept/instance, внешнее знание и выводимость из двух конкретных входов. N-статус сам по себе не основание отклонить предсказание. Для пустого выхода quality_review.csv содержит явные строки NO_POSITIVE_PREDICTION с review_applicable=False, без выдуманных вердиктов. Scores ниже 0.35 остаются диагностикой; рост score не означает правильность.

Результат не даёт corpus recall, независимой precision или причинной оценки отдельных ограничений. Отдельно различаются нехватка исходных посылок, crop 512, отсутствие общего утверждения, неподтверждённая пригодность labels и гипотезы о span-pair classifier/структуре input. Предлагается следующий минимальный опыт, но он не выполняется.
