# Шаблоны Stage 3A.5.10

Действующая версия `3A.5.10-v1`. Канонические строки `SYSTEM_PROMPT`, `OUTPUT_FORMAT` и сборщик `messages_for` находятся в [llm_context.py](../../../src/cgraph/llm_context.py). Каждый запуск записывает точные сообщения и SHA-256 их сериализации.

- System задаёт роль исследовательского ассистента, язык вопроса, правила цитирования, атрибуции, работы с противоречиями и неопределённостью. Инструкции в документах объявлены недоверенными. Ответ сохраняет числа, единицы, отрицания и ограничения, различает наблюдения, гипотезы, интерпретации и наблюдаемую причинность.
- User передаёт JSON с полями `question`, `allowed_citations`, `response_format` и `sources`. У каждого источника есть ID, документ, ревизия, заголовок, URL, SHA, offsets и исходный текст. Маркеры чата внутри JSON экранируются. Декодированный исходный фрагмент совпадает с corpus slice.

Ответ API содержит три поля. `status` принимает ANSWERED, PARTIAL или INSUFFICIENT_EVIDENCE. `blocks` — массив объектов с `text` и непустым массивом `citations` для каждого утверждения. `limitations` — массив строк, обязательный с объяснением для PARTIAL и INSUFFICIENT_EVIDENCE. У отказа массив блоков пуст. CLI дополняет ответ нормализованными ссылками и метаданными. JSON Object Mode контролирует представление ответа у Groq, форма и разрешённые ID проверяются локально.

Цитаты проверяются структурно. Даже при верной ссылке возможна неправильная интерпретация или чрезмерное обобщение. Инструкции и разделение ролей снижают риск prompt injection. Структурная проверка не оценивает выполнение произвольной инструкции, если ответ сохраняет допустимую схему. Инструменты и функции модели в этом пайплайне отсутствуют.
