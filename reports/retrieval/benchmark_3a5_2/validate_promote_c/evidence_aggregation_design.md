# Evidence Aggregation — контракт первого прототипа

Агрегатор принимает provenance-валидные факты из нескольких выбранных путей одного запроса и организует их по аспектам вопроса. Порядок исходного ранжирования остаётся доступен потребителю. Путь между всеми источниками не требуется.

## Вход

- `query` содержит исходный текст запроса и необязательные source-exact spans его аспектов. Если spans не переданы, первый прототип использует детерминированное разбиение по знакам препинания и явным сочинительным связкам. Для простого вопроса остаётся один аспект.
- `ranking` содержит `namespace`, `graph_fingerprint`, упорядоченные пути с `path_id`, ранги и исходные evidence bundles. В обработку входят только bundles с валидной навигацией, полными валидными `RELEX_REL` и окнами с provenance.

## Выход

- `facts[]` содержит отдельные исходные факты с ключом `(document_id, source_triple_id)`, оригинальным предикатом и направлением `head_id → tail_id`. Отдельно сохраняются соответствующие физические ключи endpoints и рёбер. Каждый факт ссылается на все поддерживающие `path_id`, а его `windows[]` хранит `window_id`, `revision_id`, `text_sha256`, `start`, `end`, точную цитату и URL.
- `aspects[]` содержит span аспекта вопроса, ссылки на факты и совпавшие термины. Детерминированное совпадение терминов с именами концов ребра и предикатом даёт сигнал `candidate_support`. Совпадение только в окне помечается `window_context_only`. Если сигнала нет, статус аспекта `uncovered`. Эти статусы пригодны для выбора фактов к проверке, а полнота смыслового ответа оценивается отдельно.
- `navigation[]` хранит исходные `SIMILAR_TO` и `HAS_SHARED_CONCEPT` с указателями на пути. Навигация не участвует в оценке покрытия фактами. Поля `namespace` и `graph_fingerprint` связывают весь набор с одним снимком.

## Сборка

1. Пройти выбранные пути в порядке ранга. Скопировать каждый валидный исходный триплет в его документе. Дедуплицировать окна по `(document_id, revision_id, window_id, start, end)`. При повторном source triple сохранить ссылки на пути. При несовместимых копиях одного триплета исключить конфликтующий элемент и записать причину.
2. Сопоставить факты с аспектами детерминированно. При равном сигнале сортировать по лучшему исходному рангу и ключу источника. Сохранять неподтверждённые аспекты видимыми.
3. Собрать evidence из выбранных документов независимо. Сохранить исходные предикаты и направления. Связи между фактами ограничиваются указателями на общий аспект и общие пути. Из семантической близости или совместной принадлежности концепту причинные связи не выводятся.

## Проверка прототипа

- Два несвязанных пути из разных документов дают два исходных факта и два аспекта. Проверить вопросы с тремя источниками и вопросы с неполным покрытием.
- Один source triple из нескольких путей или в обратном traversal представлен единожды. Различные исходные триплеты с одним окном остаются самостоятельными.
- Неверные offsets, revision или конфликтующие свойства исходного триплета приводят к отклонению записи. Валидные Unicode-срезы сохраняются побайтово.
- Путь с семантическим мостом или концептуальным membership не создаёт факт. Фактическое направление остаётся исходным даже при обходе в обратную сторону.
- Проверить детерминированность при перестановке входов с фиксированными рангами и эквивалентность при повторе путей.
- На фиксированных Gold сравнить с прямой выдачей путей число независимых триплетов, покрытие частей вопроса и долю фактов, полностью подтверждённых ручным аудитом. Отдельно учесть противоречия и окна, которые пересекаются с Gold без подтверждения нужного утверждения.

Прототип предполагается отдельным офлайн-модулем без LLM. Production EvidenceExtractor остаётся источником проверенных цитат.
