# Stage 3A.5.5 — Entity Linking

**Production-профиль `0.85 / top_k=10 / baseline`.** Recall@5 и factual recall выросли с **44/56 до 47/56**. Полное покрытие выросло с **23/35 до 26/35**. Недостающие источники утверждённых C03 и C07 остались за пределами кандидатных путей. Conditional и Expansion доступны как экспериментальные режимы.

## Входы и метод

- 35 вопросов. Утверждённые A01–A08, B01–B07, C01–C10 и десять исторических формулировок C. Общий знаменатель document recall — 56 пар вопрос–документ. В JSON исторические и утверждённые C различаются префиксом группы.
- GLiNER E3 с порогом `0.15`, E5-small-v2 и 811 замороженных векторов имён. По каждому из 228 уникальных текстов выполнено одно кодирование. На диске сохранена матрица float64 из 184 908 cosine scores. Все сравнения использовали этот кэш.
- Baseline BFS ограничен 5 переходами, 50 соседями, 200 путями, 1000 строками смежности и 32 входными seeds. Reranker A выбирает пять **путей**. Использован снимок Stage 2G.3 из Stage 3A.5.3. Сверка с архивом живого Neo4j воспроизвела порядок 2000 путей, 50 рангов A, evidence и диагностику BFS. Повторный GLiNER/E5 подтвердил список и порядок входных seeds утверждённого C с допустимым расхождением cosine до `2e-6`.
- Сравнение Stage 3A.5.2 показало потери C03/C07 до реранкинга. Stage 3A.5.3 закрепил A после проверки документной политики C. В исходной ветке `8fa1399` отдельного завершённого результата Stage 3A.5.4 нет. [Baseline 3A.5.2](block_c_retrieval.md) · [Реранкинг 3A.5.3](document_aware_report.md) · [Валидация A/C](validate_promote_c/validation_report.md)

`Candidate recall` считается по сырым Top‑k каждого поиска. `Threshold recall` использует те же кандидаты выше cosine cutoff. `Seed recall` использует документы уникальных seeds после политики fallback и входного лимита BFS. Все три значения micro. Отдельно доступны результаты до применения лимита и результаты каждой группы.

Ручной аудит C03/C07 классифицирует явно посторонние статьи по заголовкам и frozen-абстрактам. Для C03 суждение основано на наличии исследования экспрессии или генетического вмешательства. Например, сравнительная геномика диатомей и иммунное фенотипирование отнесены к посторонним, а инженерия вариантов эритропоэтина оставлена без решения. Для C07 оценивалась связь с интерпретацией и фиксацией событий. Работы о папских медалях, повествовании Книги Мормона и различии взглядов в синодальности оставлены без решения. Для A/B и holdout повторно использованы подтверждённые посторонние документы из ручного аудита 3A.5.3. Количество candidate nodes из этих источников даёт нижнюю границу числа ложных кандидатов. Упоминания вне reference set подсчитаны отдельно. Seed precision — `NOT_EVALUATED`. ## Политики fallback

- **A · Baseline.** Полный вопрос ищется при пустом NER. Порядок seeds и повторяющиеся записи воспроизводят исходный запуск.
- **B · Conditional.** Полный вопрос дополнительно ищется, если хотя бы у одного mention нет seed, содержательные токены вопроса не покрыты именами допущенных узлов или mention общий. Признак общего mention — один содержательный токен или одно и то же имя в трёх документах и более.
- **C · Expansion.** Условие B запускает поиск до четырёх дословных непокрытых фрагментов. Разделители — союзы и пунктуация. Полный вопрос тоже участвует. Каждый резервный поиск даёт не более одного нового seed.

В B/C сначала рассматриваются первичные exact matches, затем первичные vector matches и резервные кандидаты. Дедупликация идёт по `node_key`. Дополнительных seeds максимум шесть. Порог применяется ко всем seeds, включая точные совпадения имён. У fallback-кандидатов есть оригинальный `query_span` с символьными offsets. Cosine выражает сходство для поиска. Поля и значение `Seed` сохраняют существующий контракт.

Из-за порядка и бюджета BFS больший seed pool не всегда даёт больше полезных путей. `0.85/10/A` добавил обязательные документы для утверждённых C01 и C02 и исторического C08. При `0.90/5` нагрузка и число посторонних seeds сократились, но исторический recall упал с 16/20 до 12/20. Профиль `0.85/20/B` дал утверждённому C ещё один обязательный документ по сравнению с выбранным режимом, при этом holdout потерял два.

Вклад E5 оценён суммой измерений по уникальным текстам запроса, каждый из которых кодировался отдельно. Сетевая задержка Neo4j и вариативность повторных замеров не измерялись. В отдельном процессе replay без моделей пиковый RSS после linking и после retrieval — 338 и 366 MiB соответственно. JSON содержит общий пиковый RSS процесса.

## Production и проверки

Обычная точка входа для выбранного профиля — `EntityLinker.for_retrieval(cache)`. Явный исторический baseline — `EntityLinker(cache, min_score=0.85, top_k=5, fallback="baseline")`. Конструктор с `min_score=None` по-прежнему возвращает только кандидатов.

- `src/cgraph/entity_linking.py` — настраиваемые политики, provenance и проверенный профиль.
- `tests/test_entity_linking.py` — регрессии совместимости, точных совпадений, лимита, дедупликации, source spans и fallback после пустого результата первичного поиска.
- `reports/retrieval/benchmark_3a5_2/run_entity_linking_sweep.py` — воспроизводимый runner.
- `reports/retrieval/benchmark_3a5_2/entity_linking_manual_audit.json` — разметка явно посторонних документов для C03/C07.
- `reports/retrieval/benchmark_3a5_2/entity_linking_sweep.json` и `reports/retrieval/benchmark_3a5_2/entity_linking_sweep.md` — детальные результаты и отчёт.

**98 тестов прошли.** Набор охватывает entity linking, query analysis, retrieval types, graph retrieval и path reranking. Совпадение seeds production-профиля с измеренным вариантом проверено по всем 35 вопросам на том же кэше. Повторный baseline воспроизвёл пути, метрики и диагностику первого прохода.

## Воспроизведение

Запуск из корня отдельного worktree. Нужен Python 3.11 из окружения с зависимостями `benchmark` и `relex`. Параметр `--assets-root` указывает на checkout с локальными `.cache/semantic_concept_sweep` и `artifacts/ner_v2/models/gliner25`. Файлы E5 читаются по путям закреплённого embedding manifest. Файлы моделей и граф проверяются хешами. Каталог `--score-cache` повторно используется при идентичных входах. `--output` должен быть новым путём.

```powershell
& "../Graph-RAG-news-analytics-system-RESEARCH/.venv/Scripts/python.exe" reports/retrieval/benchmark_3a5_2/run_entity_linking_sweep.py `
  --assets-root ../Graph-RAG-news-analytics-system-RESEARCH `
  --score-cache .cache/stage_3a55_reproduction_scores `
  --output .cache/stage_3a55_reproduction.json `
  --manual-audit reports/retrieval/benchmark_3a5_2/entity_linking_manual_audit.json `
  --e2e 0.85 5 conditional --e2e 0.85 5 expansion --e2e 0.85 10 baseline `
  --e2e 0.90 5 baseline --e2e 0.90 5 conditional --e2e 0.90 5 expansion `
  --e2e 0.85 20 conditional --e2e 0.80 50 conditional `
  --e2e 0.85 10 conditional --e2e 0.85 10 expansion
```
