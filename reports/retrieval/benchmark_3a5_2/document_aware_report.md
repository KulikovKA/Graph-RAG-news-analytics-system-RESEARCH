Обе экспериментальные политики подняли покрытие Gold-документов с **13/21 до 17/21**, а число вопросов со всеми Gold-документами в Top-5 выросло с **2/10 до 6/10**. На этих метриках B и C равны. C сохранил исходные Top-5 целиком у обоих контрольных вопросов C04 и C10. B сохранил покрытие обоих, при этом заменил пятый путь C04. Этого офлайн-теста достаточно, чтобы выбрать C для следующей проверки на новых вопросах. Для переноса в production пока нужна независимая проверка релевантности фактов.

## Точное воспроизведение A

Baseline зафиксирован коммитом `ab9c8f56b96e7cda6c0621f33dd6942bbd84d367` и SHA-256 архива `91045d2e50fd31809fd2fe2951f34ed2b7144b43d9ae8924a6725a51e43374fa`. Из сохранённых 2 000 путей исходный `rerank_paths` допустил 1 875. Во всех десяти запросах совпали порядок **50/50** Top-5 path IDs, `base_score`, `score`, все компоненты `score_breakdown`, метрики отдельных путей, исключения и диагностика. Сравнение чисел выполнено без допуска. Настройки baseline и заморозка кандидатов описаны в [исходном отчёте](block_c_retrieval.md).

Точность относится к ранжированию по сохранённым решениям upstream-валидации. Компактный архив сохранил factual source relations, результаты проверки навигации и graph fingerprint на уровне retrieval. В нём отсутствуют полные исходные свойства рёбер и документов, их индивидуальные fingerprints и сырые trust-флаги `resolution_decision_2f2`, `requires_review` и `review_status`. Поэтому независимая перепроверка этих live-свойств по архиву невозможна. Replay использует зафиксированные upstream-решения и отклоняет архив с другим SHA-256. Для factual provenance отдельно сверены document ID, source triple ID, revision, хеш, оригинальный текст и Unicode offsets с frozen-корпусом. Модели, Neo4j, BFS и LLM в эксперименте не запускались.

## Почему A теряет документы

Исходный lexical score использует термины окон целиком. Когда разные рёбра ссылаются на одно окно полного abstract, они получают одинаковый relevance и сохраняют отдельные места благодаря разным исходным фактам. Для двух одношаговых путей с разными рёбрами из того же окна Jaccard по рёбрам равен нулю, по окнам и документам — единице. Итоговый штраф `0.75 × (0.30 + 0.20) = 0.375` применяется по максимальному overlap с одним предыдущим путём. Он не растёт с каждой новой выдачей того же документа. Само совпадение лексики в окне может быть связано с другой частью abstract, чем выбранное ребро.

В C02 пять путей W3123056951 получили одинаковые base scores `2.6940`. После первого выбора их scores оставались `2.3190`, выше лучшего пути W2761455282 с base score `2.1000`. В B дополнительные `−0.65` опустили повторный путь до `1.6690`. C поставил документ W2761455282 вторым по профилю и выбрал его лучший доступный путь. В обоих случаях `0648be3f7c41…` занял второе место.

## Политики

Параметры B и C зафиксированы до запуска отбора и оценки по Gold. Все три политики получили один пул и те же исходные base scores. B и C переиспользуют тот же gate для trusted navigation и provenance и тот же Jaccard. В их качественном отборе участвуют пути с ненулевым лексическим покрытием и base score не более чем на **1,0** ниже лучшего в пуле. Если такие пути исчерпаны, оставшиеся места заполняются исходной оценкой, без дополнительного поощрения документа. Gold загружается после построения всех выдач.

| Политика | Как выбирает пути |
|---|---|
| A | Исходный `rerank_paths` с `RELEVANCE_WEIGHT=3.0`, `FACTUAL_WEIGHT=1.0`, `DIVERSITY_WEIGHT=0.75`. |
| B | Исходный score со штрафом **0,65 × доля уже представленных фактических документов пути**. Для идентичных наборов фактических источников действует исходное исключение дублей. |
| C | Сначала оценивает документ по лучшему допустимому пути. Лучший следующий путь с непересекающимися исходными триплетами того же документа даёт прибавку до **0,15**, пропорционально локальному покрытию терминов. В первые **3** позиции при наличии кандидатов выбирает лидеров ещё не представленных документов. Остальные позиции заполняет по исходному score. Полностью повторные наборы исходных триплетов исключаются. |

В C документ допускается в профиль только при совпадении хотя бы одного термина вопроса в его собственных фактических окнах. Базовая оценка смешанного пути по-прежнему отражает суммарную лексику его окон. В этом пуле путей с фактами из разных документов нет. Профили и объяснения слотов сохранены в JSON. ID источника для новизны и учёта дублей — пара `(document_id, source_triple_id)`. Если путь приносит новый триплет и частично повторяет предыдущий, его полный исходный evidence сохраняется, а повтор отражается в метрике. При равенстве score выбор детерминирован по path ID или document ID. `SIMILAR_TO` и `HAS_SHARED_CONCEPT` могут привести к другому документу, но не дают ему фактологического веса.

`GoldDocRecall` учитывает все документы на выбранном пути. `FactualGoldDocRecall` требует provenance-валидный факт из самого документа. Числа совпали для каждого вопроса и политики в этом прогоне. `EvidenceWindowOverlap` требует положительное пересечение двух диапазонов в той же ревизии документа. Пересечение с окном не устанавливает, что выбранное ребро выражает целевой факт. Повторные source triples считаются сверх первого вхождения в пределах одного вопроса. Оба повтора во всех режимах относятся к C05, где несколько путей повторяют один факт и добавляют другие исходные триплеты.

## Что изменилось

- C01, C02, C06 и C08 вернули соответственно **W2791492120**, **W2761455282**, **W3101922761** и **W7215137876** в обеих политиках. Их новые фактические пути имеют префиксы `471989f60c05`, `0648be3f7c41`, `8828792cefd3` и `377102676e06`.
- C05 остался с W4309030044. Лучший путь W2906067930 `c0405ec6b625…` имеет base score **1,8334**, при максимуме **2,9331** и заранее зафиксированной границе **1,9331**. Он присутствовал в пуле, но качественный отбор его отсеял. Широкие окна способны дать преимущество иному исследованию даже при релевантности обоих.
- Оба контроля C04 и C10 сохранили все Gold-документы и 6/6 и 3/3 пересекающихся окон соответственно. C сохранил обе исходные выдачи. B добавил W3101922761 в C04 вместо другого пути W1979727947, который остался представлен путём на первом месте.
- Отрицательные контроли сохранили исходные пропуски. **W2039836112** (C03), **W2326480042** (C07) и **W2084709926** (C09) отсутствовали в замороженных кандидатах. Потолок этого пула составляет **18/21** Gold-привязок и **7/10** полных reference sets.

C предпочтителен для следующей офлайн-проверки: он достигает тех же наблюдаемых Gold-метрик, сохраняет обе контрольные выдачи и выделяет меньше мест документам, чья релевантность не подтверждена Gold. Это наблюдение относится к десяти вопросам. Перед внедрением нужно подтвердить эффект на новых вопросах и вручную оценить точные факты из добавленных путей, особенно для C01, C02, C06 и C08.

## Воспроизведение и тесты

Из корня репозитория, Python 3.11. Запуск без `--output` проверяет только режим A. С `--output` runner сначала проверяет A, затем выполняет B и C и записывает новый JSON.

```powershell
python -B reports/retrieval/benchmark_3a5_2/run_document_aware.py
python -B reports/retrieval/benchmark_3a5_2/run_document_aware.py --output reports/retrieval/benchmark_3a5_2/document_aware_repeat.json
python -B -m pytest reports/retrieval/benchmark_3a5_2/test_document_aware_reranking.py tests/test_path_reranking.py tests/test_evidence_extraction.py -q
```

Прошли **73 теста**, включая 11 новых синтетических проверок. Проверены два релевантных документа при избытке повторных путей, защита от вытеснения сильных путей нерелевантным документом, независимость source triples, доверенные и недоверенные мосты, точные offsets и детерминированность при перестановке входов. Повторный прогон с `PYTHONHASHSEED=314159` побайтово воспроизвёл JSON. Все 150 выбранных позиций сверены с архивом и оригинальными evidence. Production pipeline, frozen corpus и Gold остались в исходных версиях.
