Откат исследовательских профилей состоит в использовании существующих production entry points.

**Гипотеза.** Перераспределение фиксированных 32 seed или пяти слотов в пользу разных частей вопроса и фактических источников увеличит покрытие обязательных документов при сохранении качества контролей. Эксперимент может опровергнуть гипотезу потерями A/B, посторонними источниками, несопоставимой стоимостью или отсутствием выигрыша.

**Контроли.** Production C означает EntityLinker.for_retrieval, TraversalLimits() и rerank_paths(policy="C"), то есть D из 3A.5.7. Отдельный репликационный контроль B использует K=5/200 с тем же C. Их не объединяем. Соглашения о входах, лицензиях и воспроизведении наследуются из контрактов корпуса и [3A.5.7](../benchmark_3a5_2/INTEGRATED_BENCHMARK_README.md). Только локальные ранее разрешённые данные, без перераспространения весов и полнотекстового корпуса. Требуем совпадение SHA корпуса и lock, моделей, кэша entity names, графа и снимка с [якорем B](../benchmark_3a5_8/FROZEN_B.json) и исходным COMPLETE manifest. GLiNER 0.15, E5-name cosine 0.85, seed 42. Offline snapshot adapter и production extractor воспроизводят физическую ориентацию, document/revision/hash и полуоткрытые offsets.

**Дизайн.** После воспроизведения контрольных рангов и диагностики сравнить по одной замене относительно production:

- Linking: дедупликация до cap, round-robin по mentions, ограниченное расширение K до 20 при отсутствии продуктивного кандидата, резервные seeds по фрагментам вопроса. Сравнить вклад K=5 и 10 при одинаковом BFS. Использовать исходные scores, связанные с текстом, версиями и fingerprint. У нового фрагмента свой точный диапазон.
- BFS: FIFO, штатный seed-fair, FIFO с приоритетом начальных узлов с ненулевой фактической степенью. Структурный индекс строится один раз по тому же снимку, его стоимость указывается отдельно. Пределы 5 hops, 50 соседей, 100 путей (200 у B), 1000 строк отношений, 32 seeds. Для установления причин допустим отдельный диагностический обход с изменением одного лимита.
- Top-5: исходный C и один отбор по свежести фактического документа внутри префикса C из 3A.5.8. Сохранить первый путь C, среди путей с новым source triple предпочесть ещё не представленный фактический документ с совпадением терминов вопроса и источника, затем исходный порядок. Варианты 20/50/100, и тот же эксперимент на B. Префикс требует C на полном пуле, поэтому бюджет не ограничивает исходный scoring.
- Для совместной проверки взять лучшие компоненты по approved factual micro, далее меньше off-Gold источников, затем меньше изменений относительно production. Для компонентов с нулевым выигрышем допускается базовый уровень. Также сравнить комбинацию лучших *изменённых* компонентов с отдельными изменениями. HOLDOUT только описание зафиксированного контроля/финалиста после выбора. Никаких ID, Gold или сведений о принадлежности вопроса группе внутри ranking/linking/traversal. Набор A/B/C уже использовался в прошлых исследованиях.

**Измерения.** На одном вопросе множество фактических документов берётся из валидных RELEX_REL с исходными цитатами. FactualGoldDocRecall@5 micro = сумма мощностей пересечений с обязательными документами / сумма обязательных, macro = среднее долей. AllRequiredDocs@5, EvidenceWindowOverlap, doc-first nDCG и MRR следуют [3A.5.8](../benchmark_3a5_8/METHODOLOGY.md). Отдельно считать полноту по фактическим документам, уникальные документы, повторы source triples и off-Gold. Парные числители и знаменатели, без вывода о значимости. Замерять elapsed p50/p95 на вопрос по стадиям, включая работу нового селектора, и peak RSS процесса. CPU, один процесс, до 4 потоков, RSS до 8 GiB, до 2 часов, 0 внешних запросов и токенов, без генерации. Останов при несовпадении якорей, корпуса или provenance. Snapshot/cache latency указывать отдельно от затрат online NER/E5 и Bolt.

**Выбор.** Для promotion нужны строгий выигрыш approved factual micro, отсутствие потерь factual hits и overlap на A/B и снижения AllRequired, воспроизводимость, source-exact provenance, отсутствие новых явно посторонних источников по аудиту, проверка смысловых переформулировок и p95 snapshot pipeline до 2x контроля при сопоставимых затратах. Ориентир 95%. При провале оставить C. При количественном выигрыше и неполной внешней валидации кандидат остаётся исследовательским. Набор из 25 вопросов мал, источники могут пересекаться, Gold неполон, окно может включать весь abstract.

**Проверки.** Пересчитать метрики по сохранённым рангам, сверить хеши и каждый выбранный срез корпуса. Тесты покрывают пустые входы, дубли, циклы, недоверенные мосты, детерминизм и бюджеты. Для каждого пропуска сохранить промежуточные множества/ранги и идентификаторы; достижимость и достаточность цитаты проверять отдельно. Сравнить повторные выдачи. Единица ручного аудита — вопрос, ранг пути, источник и направленное утверждение. Проверить тематическую релевантность, обе сущности, предикат, направление, атрибуцию, отрицание, причинность и достаточность окна. Для Precision@5 нужны решения по всем пяти позициям заранее определённого вопросного набора (пустые позиции дают 0) и согласование спорных случаев. Частичный аудит не даёт Precision. Отдельная независимая разметка новых вопросов нужна для внешнего подтверждения.

### Уточнение после диагностики контролей, до матрицы

У production C05 и C09 есть seeds потерянного документа без достижимого factual witness. Добавляем одно самостоятельное сравнение rescue. Для принятого seed без прямого физического факта выбираем ближайшую по той же cosine-строке продуктивную сущность того же документа. Оставляем query mention, требуем cosine ≥0.80 для замены, при отсутствии альтернативы сохраняем seed. Измеряем отдельно от увеличения K, дедупликации и смены BFS. Вторая однофакторная проверка — K=20 с исходным порядком, чтобы установить цену усечения. Дополнительная пара запросов A/B и четыре C зафиксированы в paraphrases.json до матрицы. Это стресс-тест тех же намерений, без независимого Gold.

### Последний эксперимент после однофакторной матрицы

Все чисто mention-based варианты оставили три общих пропуска. До просмотра HOLDOUT и результатов переформулировок фиксируем ещё один вариант query-only fallback. BM25 по заголовку и abstract всех 30 документов (k1=1.2, b=0.75) предлагает не более двух источников с положительным score. В каждом выбираем прямую продуктивную вершину с наибольшим E5 cosine по исходным mentions, добавляем её в начало того же бюджета 32 seeds. Порог 0.85 продолжает применяться к обычному linking; у резервного канала условие допуска — положительный BM25. Сохраняем ID, cosine и диапазон исходного запроса отдельно от документного score. Это гибридный поиск источника и вершины. Проверить его отдельно при production K и в совместном профиле, учитывая стоимость индекса и поиска. Следующих раундов настройки на этих 25 вопросах не планируется.
