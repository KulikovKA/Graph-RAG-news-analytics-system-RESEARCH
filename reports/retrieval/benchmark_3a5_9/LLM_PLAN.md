# Следующий этап · сравнение генерации

Перед запуском зафиксировать модель и revision, SHA весов, tokenizer, шаблон сообщений, decoding, seed, максимальный контекст и бюджет ответа. Один и тот же frozen corpus, единица оценки — один вопрос, одинаковый порядок вопросов и одинаковый потолок контекстных токенов для retrieval-систем. Вести учёт фактически упакованных источников, потерь при усечении, пустой выдачи, отказа отвечать и стоимости. Контроль без retrieval получает тот же вопрос и инструкцию ответа. Системе разрешён обоснованный отказ при недостаточном контексте.

| Условие | Контекст для модели |
|---|---|
| LLM без retrieval | Только вопрос и инструкция |
| LLM + Vector RAG | Independent vector index по тем же документам, зафиксированные chunking/overlap, embedding revision, Top-K, упаковка и идентификаторы цитат |
| LLM + Graph-RAG C | Production-профиль [PROFILE.json](PROFILE.json), фактические источники и окна в порядке C |
| LLM + улучшенный Graph-RAG | Добавлять после отдельного подтверждения retrieval-профиля. В Stage 3A.5.9 принят KEEP_C. |

Для обеих retrieval-систем упаковывать цитаты с document ID, revision и диапазоном. Проверять границы после токенизации. Сохранять физические роли head/tail и тип отношения. Маркировать навигационные переходы отдельно, чтобы генератор мог отличить контекст поиска от проверяемых утверждений.

Сформировать новый набор до генерации: независимый автор составляет вопросы и обязательные компоненты из исходных текстов без доступа к выдаче, второй проверяет ответимость, альтернативные релевантные источники, отрицание, атрибуцию и доказательные диапазоны. Выделить срез недостаточной информации и многодокументные вопросы. Дедуплицировать близкие формулировки и семейства вопросов относительно уже исследованных A/B/C и historical C. Заморозить текст, роли и хеши до выдачи систем. Показывать ответы экспертам в случайном порядке без названий систем. Разногласия сохранять до арбитража. Шесть текущих переформулировок пригодны для повторного стресс-теста.

| Метрика | Единица и расчёт |
|---|---|
| Groundedness | Доля проверяемых атомарных утверждений, выводимых из предоставленного контекста. У контроля без контекста показатель неприменим. Отдельно учитывать ответы без утверждений. |
| Factual accuracy | Доля проверяемых утверждений, подтверждённых frozen источниками при правильных субъекте, направлении, отрицании, масштабе и атрибуции. Оценима и у контроля без retrieval. |
| Citation precision | Доля предъявленных связок «утверждение — цитата», где ссылка разрешается до точной ревизии и фрагмент подтверждает утверждение. Нулевой знаменатель фиксировать отдельно. |
| Полнота | Доля заранее размеченных обязательных компонентов ответа, правильно раскрытых для каждого вопроса. Отдельно оценить правильность отказов. |
| Hallucination rate | Отдельные доли противоречащих источнику и неподтверждаемых утверждений среди проверяемых. Для вопроса также индикатор наличия хотя бы одного такого утверждения. |
| Latency и token cost | Cold/warm, p50/p95 retrieval, time-to-first-token и end-to-end. Число входных/выходных токенов, модель и зафиксированный тариф для денежной оценки или CPU/GPU-секунды для локальной модели. |

Публиковать парные различия по одному и тому же вопросу, числители, знаменатели, неопределённость по вопросам и примеры ошибок. Настраивать prompts и Vector RAG только на отдельном development split. Вывод об улучшении требует совпадающих бюджетов, источников и условий генерации.
