## Provenance и текст

Runner проверяет envelope и происхождение путей из cache keys B, сравнивает документы с замороженным корпусом, заново строит bundles через `extract_evidence` и требует точное совпадение. Production gate C исключает пути без фактического ребра, с невалидным factual evidence, несовпадением graph fingerprint или недоверенной навигацией. Нейросетевая селекция повторно применяет этот gate. Входные имена head и tail берутся из замороженного файла 811 представлений с контролем принадлежности документа. Ориентация каждого `RELEX_REL` сохраняется физической, а движение против направления отмечается отдельно. `SIMILAR_TO` и `HAS_SHARED_CONCEPT` представлены как навигация.

- `fact_focused` показывает навигационные шаги и тройки в порядке рёбер, затем provenance windows по документу и offsets.
- `document_aware` показывает навигационные шаги и группирует факты и окна по документам. Внутри документа факты идут в порядке рёбер, окна — по start, end и window ID.

Шаги пронумерованы индексом в пути. Дословные окна дедуплицируются по документу, offsets и window ID внутри текста пары. Результат сохраняет полную привязку каждого выбранного источника. Строки о навигации не дают основания приписывать факт соседнему документу. Ранжирование воспроизводит назначение и происхождение извлечённых фактов, а их научная корректность ещё требует проверки.

В энкодерах вопрос и представление кодируются как пара. При превышении длины отсекается правый хвост второго сегмента. Каузальные модели используют шаблон издателя, правый хвост токенов убирается только из участка Document, а вопрос и suffix ответа сохраняются. В `document_aware` ранние группы могут вытеснять поздние документы. В `fact_focused` приоритет получают заголовки троек, затем окна. Во всех случаях логируются исходные и оставшиеся непаддинговые токены, число и доля удалённых токенов. При недостаточном лимите для вопроса и рамки runner выдаёт ошибку. Отсечение относится только к входу модели, eval читает полные исходные evidence bundles.

## Ranking

Сначала C исполняется на полном BFS, и результат сравнивается с замороженным C. Упорядоченный префикс состоит из максимум пяти путей production C. Остальные допустимые пути сортируются по убыванию `base_score` C без greedy diversity, при равенстве по `path_id`. Для этого score вычисляется оригинальным C на singleton. Действительный порядок preselection сохраняется. Такой префикс гарантирует, что вариант C и обе политики сравниваются в одном бюджете. Рассмотрение большего бюджета расширяет тот же порядок, включая пути с повторяющимися источниками.

- `heuristic_C` воспроизводит оригинальный выбор C.
- `neural_only` сортирует по сырому значению конкретной модели.
- `hybrid_C_neural` усредняет percentile позиции preselection C и percentile нейросетевого score с весами 0.5/0.5. Percentile имеет вид `1 − (rank−1)/(N−1)`, одинаковые neural scores получают средний ранг, единственный путь получает 1.

Для обеих нейросетевых политик итоговые равенства разрешаются по `path_id`. Выбор идёт по убыванию score, путь должен добавить новый валидный ключ `(document_id, source_triple_id)`. Это тот же барьер повторов, что у C. Другие компоненты C, включая документные слоты и greedy diversity, содержатся в контрольной политике. Score разных моделей допускается сравнивать только через измеренные metrics. Веса гибрида заданы заранее, чтобы исторический HOLDOUT оставался описательным срезом. Пул варианта C имеет другой linking Top-K и потребовал бы отдельного эксперимента. Общий барьер повторов удерживает правила выбора постоянными между двумя нейросетевыми политиками, поэтому дополнительный diversity-коэффициент в основной сетке отсутствует.

Уровни фиксированы по относительным размерам в этой подборке. Для Qwen и Mixedbread разность логитов монотонно эквивалентна вероятности положительного класса в двухклассовом softmax. Inference вычисляет только logits последней позиции, с left padding и attention mask. Выход типизирован одним конечным score на пару. У Ettin используется локальный штатный forward CrossEncoder с identity head и отдельным учётом токенизации. Размер головы и pinned weights фиксируются реестром. Все файлы загружаются локально с `trust_remote_code=False` и `use_safetensors=True`. Для Qwen проверяются опубликованные SHA-256 оригинального reranker и ID обученных ответных токенов. Требования к модульной версии Ettin отражены в Windows CPU lock. [Описание модулей CrossEncoder](https://www.sbert.net/docs/cross_encoder/usage/custom_models.html)

## Метрики и время

GoldDocRecall использует `path.document_ids`, FactualGoldDocRecall — только документы валидных источников. Micro делит количество найденных документов на общее количество обязательных. Macro усредняет значения по вопросам. AllRequiredDocs проверяет покрытие каждого обязательного документа. EvidenceWindowOverlap использует совпадающие document ID и revision ID и хотя бы один общий символ. Некоторые окна покрывают весь abstract, поэтому эта метрика не измеряет точность положения факта.

Doc-first nDCG@5 суммирует число впервые найденных factual Gold-документов на каждом ранге пути с дисконтом `1/log2(rank+1)` и делит на число обязательных документов. Идеал задаёт их одновременное появление на первом пути. MRR@5 использует первое появление любого factual Gold, ноль при отсутствии. Для метрик нет независимой оценки релевантности отдельных путей. Повторы окон считаются по документу, ревизии, хешу и offsets. Типы переходов считаются по физическим рёбрам. Off-Gold может быть релевантным. Отчёт учитывает все документы путей и отдельно off-Gold документы фактических источников. Semantic Evidence Coverage остаётся `NOT_EVALUATED`.

Oracle recall рассчитывает union найденных документов до выбора пяти путей при 20/50/100/200 и отдельно проверяет factual evidence. Он служит верхней границей доступности документов при данном preselection, с возможным завышением достижимости в пяти путях. Диагностика показывает три разных пропуска: вне raw BFS, вне полного provenance-eligible пула и вне neural budget. Парные дельты сравнивают одни и те же успешно завершённые вопросы с C. Значимость и независимая обобщаемость не заявляются.

По умолчанию порядок соответствует реестру, устройство CPU, float32, SDPA, 4 intra-op threads, 1 inter-op, seed 42, batch 4 и sequence limit 512. Модели работают последовательно. На одну загрузку выполняется один исключённый из latency warmup batch. Память — максимум RSS процесса с опросом каждые 50 мс, включая пул данных и инфраструктуру. Очень короткие пики могут остаться между измерениями. p50/p95 для C измеряют вызов C. Для нейросетевых политик p50/p95 включают preselection, render, tokenization, inference и общий выбор двух политик. Load, warmup, хеширование, Neo4j, GLiNER, E5, расчёт метрик и запись результатов исключены из этой latency. Pairs/sec — число пар за секунду inference, включая передачу и синхронизацию тензоров. При повторном запуске host cache и доступная память могут отличаться, поэтому manifest сохраняет попытки загрузки отдельно.

Рекомендация для следующего ручного аудита строится после завершённого полного прогона. На 25 approved вопросах требуются factual micro recall строго выше C, AllRequiredDocs не ниже C, p95 до 10 с и RSS до 8 GiB. При нескольких вариантах выбирается меньшая p95. HOLDOUT не используется для выбора весов гибрида или параметров. Протокол не даёт основания автоматически заменять production C.
