# Stage 3A.5.12 · Domain-Agnostic Contextual Shared Concepts

## Результат

На замороженном Corpus100 рассчитаны два независимых представления и
**225 конфигураций по 10 042 851 междокументной паре**. Короткие окна S0,
W8 и W16 при порогах 0,90/0,90 оставили 868, 1 045 и 918 пар после защит.
Они охватили соответственно 99, 99 и 98 документов, включая все документы
по энергетике и биотехнологиям. W128 оставило 9 056 пар. Чем шире окно,
тем выше типичный context cosine. Примеры с разными понятиями показывают,
что одного этого роста недостаточно для выбора окна.

**PASS означает прохождение фильтра кандидатов.** У Hybrid C итоговые
45 Shared Concepts и 231 membership охватывают 207 сущностей (4,59%)
и 41 документ. По энергетике и биотехнологиям у baseline по 0 из 20
документов с memberships. В новом эксперименте измеряется участие
сущностей в парах. Сравнение покрытия описывает разные единицы учёта.

### Защитные правила

Provenance проверен до scoring по исходным Unicode offsets, документу,
ревизии, привязке source ID и всем сохранённым mention ID. Несовместимый
артефакт блокирует вычисление. При 0,90/0,90 RESULT исключил 107 пар
S0 и 1 777 пар W128. Затем несовместимые типы исключили ещё 360 и
5 027. Типизация допускает пересечение меток и совместимость внутри
группы TASK, PROCESS, ATTRIBUTE, CONCEPT. Правило RESULT действует и
при нескольких метках, поэтому ошибки типизации могут скрыть реальные
соответствия.

Для раскрытий нужен общий явно засвидетельствованный short form.
Конфликт отмечается, если содержательные слова засвидетельствованных long
forms не пересекаются. Это консервативная проверка. Во всей сетке она
исключила 0 пар, срабатывание проверено регрессионным тестом. Различие
уровня абстракции оставлено ручной проверке. Например, одинаковый
тип ATTRIBUTE позволяет пройти паре «кривая ROC / площадь под кривой».

### Выборка и диапазоны для разметки

Воспроизводимая выборка содержит 302 уникальные пары. Seed 42.
В каждой страте равномерный отбор без возвращения, затем объединение по
неориентированной паре, перестановка строк и сторон. Есть 12 пар внутри
каждой из пяти тем на срезе W32 0,85/0,85, буквальные и NFC/casefold
совпадения, одинаковые имена с низким context или разными темами,
разные имена с двумя высокими cosine, оба направления расхождения
cosine, 20 исторических REJECT, 16 пар с принятыми референтами
memberships и 16 контрольных пар с низкими cosine из разных тем.
В blind CSV остаются ID, типы, исходные evidence и пустые колонки для
решения разметчика. Контрольные и диагностические случаи также идут на
разметку. Итоги разметки, Precision, Recall и F1 отсутствуют.

Для первого сравнения подходят S0, W8 и W16 с name 0,90 и context
0,85–0,90. Здесь видна разница между сохранением повторных научных
терминов и объёмом работы разметчика. W32 с теми же порогами даёт
промежуточный контроль. W64 и W128 при 0,90/0,90 нужны как
контраст для проверки тематического сходства, а 0,95/0,90 — для
страты почти одинаковых названий. Полезно сохранить пары около и
ниже name 0,75 для разбора аббревиатур. Выбор рабочей конфигурации
требует пользовательской разметки.

## Варианты будущего каталога

| Подход | Прямая проверка и обновление | Цена и риск |
|---|---|---|
| Представитель из исходного evidence | Упорядоченные пары из двух документов предлагают концепт. Один зафиксированный профиль служит представителем. Для каждого участника проверяются обе оси, тип и evidence к представителю. Новый участник проверяется так же. Версия представителя сохраняется. | У каждого участника есть короткое объяснение. Для E прошедших пар и K представителей начальная оценка `O(E log E + NKd)`, инкрементально `O(Kd)` на сущность. Частный представитель может сузить класс или соединить разные смыслы. |
| Полная попарная совместимость | Детерминированно расширять группы только при прямой проверке каждой новой междокументной связи. Допускать по одному представителю документа. При добавлении документа сверять новую сущность со всеми членами и записывать повторы evidence. | Мост через третью сущность не склеивает группы. Для группы размера m добавление требует (O(md)) без готовых scores. Все пары в худшем случае требуют (O(N^2)) памяти для кэша. Полный поиск максимальных клик экспоненциальный. Жадный вариант чувствителен к порядку, а строгая совместимость дробит классы. |
| Несколько фиксированных референтов | Согласованная пара из двух документов закрепляет две независимые пары векторов как основу версии. Индивидуальный допуск требует прямой проверки нового участника с каждым референтом. При смене референтов пересмотреть memberships на новой версии. | Прозрачны обе опоры и лучше видна полисемия одной из них. Для A референтов на концепт стоимость новой сущности (O(KAd)). Ошибочная пара и слишком узкая комбинация опор дают систематические ошибки. |

Здесь N — число сущностей, d = 384. В каждом варианте сохраняются
исходные spans, provenance проверки, версия представления и минимум
два документа. Membership не переносит факты и не создаёт RELEX_REL.
Ни один вариант группировки не утверждён и экспериментальные
memberships в Neo4j не создавались.

## Воспроизводимость и ограничения

Одна локальная сессия E5-small-v2, CPU FP32, 4 потока, batch 8,
ревизия `ffb93f3bd4047442299a41ebb6fa998a38507c52`. Записи name reuse
проверены для всех 4 506 ID по входной строке, файлам модели, реализации
и порядку исходного батча. Из 4 519 исходных spans на окно, включая
участников 13 объединений ER, сохраняются все mention IDs. Одинаковые
входы на уровне сущности имеют один вес. 39 501 уникальный вход E5
закодирован для контекста, ещё 586 использований уникальных строк на
уровне окна обслужил общий кэш. Только W128 потребовало обрезания,
у 8 spans. Векторы усреднены в float64 без повторной L2-нормализации.
Cosine полных средних использует временные нормированные копии.

Сегментатор защищает сокращения, инициалы и десятичные точки, учитывает
закрывающие кавычки и скобки, а окна сохраняют подстроки оригинала. Это
правила для англоязычных научных аннотаций. Необычные сокращения,
начало предложения со строчной буквы и отсутствие пунктуации могут
смещать границы. Два представления используют одно название, поэтому
их статистическая зависимость возможна. Corpus100 — целевая выборка из
пяти тем. Результаты с E5 и замороженными NER-типами зависят от этой
выборки. Абсолютное качество resolver, обобщение на другие корпуса
и downstream retrieval на этом этапе не измерялись.

Полный прогон занял **46 мин 24 с** до записи локального манифеста.
E5 с первой загрузкой модели занял 2 586,1 с, агрегация 3,5 с,
cosine sweep контекста со статистиками 83,2 с, name cosine со
статистиками 1,6 с. Измеренный пик RSS процесса **1,64 GiB**.
Resume с дополнительными экспортами занял 61,6 с. Счётчики памяти
снимаются с интервалом 250 мс. В MLflow `data_expansion` опубликованы
агрегаты run `e391d4c9f5ba4defaa4c1e99d7d8cfbd`.
