# Запуск Entity Linking V2

После публикации пополнения запустите команды из корня RESEARCH в Python 3.11 с установленными зависимостями проекта. Скрипты читают опубликованное поколение из `artifacts/relex_corpus100_shared_concepts_v2_no_similar_to/CURRENT.json` и используют готовые Name/S1-векторы из его `entities.json`. При другом каталоге публикации укажите `--graph-root`. GLiNER берётся из `artifacts/ner_v2/models/gliner25`, E5-small-v2 из `../embedding-models/intfloat__e5-small-v2` или пути `--e5-model`.

## Один вопрос

Запишите текст в переменную PowerShell `$queryText`. Числа в команде служат примером запуска. Без `--threshold-score` работает C1, с ним работает C2.

```powershell
$env:PYTHONUTF8 = '1'
uv run --no-sync python scripts/link_corpus100.py $queryText --threshold-name 0.80 --alpha 0.50 --top-k 10
```

JSON содержит кандидатов по упоминаниям с двумя cosine score и итоговым score, уникальные seeds с provenance и ID поколения. При отсутствии упоминаний GLiNER список seeds пуст.

## Перебор

Подготовьте размеченный JSONL до запуска. В каждой строке нужны следующие поля.

| Поле | Содержание |
|---|---|
| `id` | Уникальный ID вопроса |
| `question` | Англоязычный текст вопроса |
| `split` | `calibration` или `holdout` |
| `targets` | Непустой список объектов с `entity_id`, `document_id` и `evidence` |
| `evidence` каждого target | `revision_id` документа, полуоткрытые Unicode offsets `start` и `end`, точный исходный фрагмент `text` |
| `precision_complete` | Необязательный boolean. Установите `true` только для исчерпывающего списка релевантных сущностей вопроса |

Целевые идентификаторы и фрагменты сверяются с опубликованным поколением. Оба сплита должны быть непустыми. Один текст вопроса допускается только один раз с учётом регистра и пробелов при проверке дубликатов. При подготовке диагностического набора зафиксируйте источники и ограничения разметки. По возможности разделяйте исходные документы между сплитами и учитывайте смещение при выборе известных упоминаний и сущностей.

```powershell
$env:PYTHONUTF8 = '1'
$questionsPath = 'ПУТЬ_К_РАЗМЕЧЕННЫМ_ВОПРОСАМ.jsonl'
$runPath = 'artifacts/entity_linking_v2/after-corpus-append'
uv run --no-sync python scripts/study_entity_linking_v2.py --questions $questionsPath --output $runPath
uv run --no-sync python scripts/study_entity_linking_v2.py --questions $questionsPath --output $runPath --resume
```

Вторая команда возобновляет прерванный запуск или собирает отчёты из готовых checkpoint. Используйте те же вопросы, поколение, код и зависимости. При смене входов выберите новый каталог запуска. Подготовка scores последовательная с одним экземпляром GLiNER и одним E5. Три потока выполняют перебор на кэше. Полностью записанный кэш вопроса и готовые группы политик переиспользуются при resume.

На calibration оцениваются 380 конфигураций C1 и 1900 C2. Выбор отдельно для C1 и C2 учитывает по порядку Entity Recall, Document Recall, MRR и меньший средний объём seeds. При равенстве приоритет получают меньший K, более высокий порог Name, более высокий порог Score для C2 и меньший alpha. После записи выбора скрипт обрабатывает holdout для двух выбранных вариантов и контрольного C1 с теми же Name, Alpha и K, что у C2. Если контроль совпал с выбранным C1, он измеряется один раз. Профили из отчёта требуют утверждения.

`results.csv`, `results.json`, `diagnostics.json` и `REPORT.md` появятся в каталоге запуска. Recall считает объединение кандидатов из Top-K каждого упоминания. Document Recall использует документы-владельцы seeds. MRR и Precision ограничены первыми K объединённого списка по максимальному score, с разрешением равенства по ID. Precision сохраняется только для сплита с исчерпывающей разметкой всех вопросов. Latency включает измеренное время подготовки scores и ранжирования на кэше.
