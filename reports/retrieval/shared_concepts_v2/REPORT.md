# Shared Concepts V2 — реализация и проверка

Реализован концептуальный слой для первоначального построения и инкрементального пополнения файлового каталога. На замороженном Corpus100 подтверждены все шесть ориентиров Stage 3A.5.13 и точное совпадение набора EE-рёбер. Одна тестовая точка EC, CC и δ дала **833 концепта, 5 897 memberships, 1 585 сущностей в концептах и охват 100 документов**. Независимая сверка воспроизвела решения EC и итоговые memberships по исходным векторам. [Машиночитаемые результаты](DRY_RUN.json)

## 1. Источники и интеграция

Реализация следует утверждённым локальным документам `Shared_Concepts_V2_Implementation_Goal.md`, `Shared_Concepts_V2_Technical_Architecture.md`, `Shared_Concepts_V2_Methodology.md` и 26 схемам в `Shared_Concepts_V2_Complete_Architecture.html`. Их контрольные суммы записаны в результатах прогона.

На входе используются канонические профили после существующего NER → RelEx → ER. CLI принимает JSON профилей либо штатный чекпойнт `entity_resolution` и соответствующие исходные документы. Адаптер переиспользует построение профилей, проверяет ревизии, evidence и точные Unicode offsets. Для E5 переиспользованы существующие сегментатор, обрезка окон, inference, арифметическое усреднение и транзакционный кэш отдельных входов. Для EE вызываются правила защит Stage 3A.5.13. [Граф Corpus100](../benchmark_3a5_11/corpus100_graph/REPORT.md) · [Контекстные эмбеддинги](../benchmark_3a5_12/REPORT.md) · [EE sweep](../benchmark_3a5_13/ANALYSIS.md)

Hybrid C использовал лексический каталог и последующую валидацию семантических кандидатов. Исторический контроль при 0,83 содержит 45 концептов, 231 membership, 207 сущностей и 41 документ. V2 формирует концепты из замкнутых прямых EE-окрестностей и ведёт собственный каталог. Исходники NER, RE, ER, Hybrid C и Retrieval C и опубликованные результаты предшествующих этапов сохранены. Прогон изолирован в `artifacts/shared_concepts_v2/`. Связь `HAS_SHARED_CONCEPT` экспортируется с provenance, версией, двумя актуальными EC scores и флагами `factual=false`, `identity=false`, `fact_inheritance_allowed=false`. Экспорт файловый, операции записи в Neo4j отсутствуют. [Диагностика Hybrid C](../benchmark_3a5_11/shared_concepts_diagnostics/REPORT.md)

## 2. Соответствие архитектуре

| Компонент | Реализация |
|---|---|
| Векторизация и EE | Модель `intfloat/e5-small-v2`, ревизия модели и токенизатора `ffb93f3bd4047442299a41ebb6fa998a38507c52`. Два независимых 384-мерных вектора, окно S1 и AND с порогами 0,94 по имени и 0,86 по контексту. Точное блочное сравнение междокументных пар без Top-K. Сохранены `result_type`, `incompatible_types` и `conflicting_expansions`. |
| Инициализация B | Замкнутая окрестность состоит из seed и его непосредственных соседей. Точные совпадения множеств объединяются с сохранением всех seed IDs. Изолированные seed пропускаются. Несколько memberships у сущности допустимы. Две первоначальные суммы дают центроиды делением на размер множества. |
| EC C | Два независимых порога проверяются у каждого участника на каждом раунде. Все нарушения текущего раунда обрабатываются одновременно. Накопительная доля считается от исходного размера и сравнивается с точным дробным δ. Требуются минимум два участника из разных документов и конечные ненулевые суммы. После исключения обновляются обе суммы, затем повторяется полная проверка. |
| CC и Жаккар | Точное равенство обрабатывается по множеству ID. Строго вложенные пары исключаются из очереди. Частичные и непересекающиеся пары проверяются по двум CC-порогам. Очередь сортируется по точной дроби Жаккара по убыванию, затем по стабильным ID. При объединении из суммы двух групп вычитаются общие участники, после чего применяется EC C. |
| Защита вложенности | Пробная замена проверяет затронутые строгие включения в обе стороны, включая возможный точный дубликат третьей группы. После успешного merge обновляются сравнения изменившихся версий. Отклонённая по вложенности пара возвращается в очередь при изменении версии блокирующего концепта. |
| Именование и lineage | Имя берётся у участника, ближайшего к центроиду названия. При равенстве выбирается наиболее частое точное название, затем минимальный ID сущности. Идентификатор при append сохраняется, версия возрастает. Новые концепты и слияния получают детерминированные ID, журнал хранит seed IDs, родителей и события. |
| Инкрементальное пополнение B | EE обрабатывает новые × старые и новые × новые пары, переиспользует прежнее EE-соседство и формирует полные окрестности только затронутых seed. EC проходит по новым ID и актуальным версиям концептов в стабильном порядке. Append проверяет новый вектор до обновления, затем всех участников на обеих новых суммах и сохранение вложенности. Отклонение оставляет предыдущий состав целым. Новые окрестности проходят EC C и общую CC-дедупликацию. |
| Состояние и восстановление | Отдельный EE-чекпойнт и общий EE-кэш для конфигураций. Чекпойнт каталога содержит очередь, версии, журнал, отклонённые пары и их зависимости. Публикация завершённого поколения выполняется атомарной заменой файлов и проверяется по SHA-256. Входы, recipe, версия ПО и конфигурация входят в идентичность прогона. |

Имя и контекст сравниваются косинусом в float64. Временные единичные представления используются при сравнении. Хранимый контекст остаётся арифметическим средним уникальных окон, а две суммы концепта сохраняют исходные нормы участников. На вход E5 подаётся `query: <name>` или `query: <name>. <window>`, лимит 512 включает служебные токены; результат masked mean проходит индивидуальную L2. Валидный seed может быть исключён по общему правилу EC с δ. Повторный вход того же ID с идентичным профилем даёт no-op.

## 4. Сложность

Здесь `N` — число сущностей, `U` — размер инкремента, `d=384`, `B=128` — размер блока EE, `m` — число принятых EE-пар, `M` — число активных концептов, `k` — размер группы, `t` — число EC-раундов, `q` — число записей CC-очереди с учётом ещё не извлечённых старых версий.

| Фаза | Время | Дополнительная память |
|---|---|---|
| EE | Начальное `O(N²d)`, инкремент `O(UNd)`. Проверки защит применяются к прошедшим оба порога. | `O(Nd + BN + N + m)` для векторов, блоков и разреженного соседства. |
| Сырые окрестности и суммы | `O((N+2m)d)` на обработку множеств и суммы, дополнительно сортировка ID в окрестностях. | `O(N+m)` для окрестностей до учёта каталога и журнала. |
| EC с δ | `O(tkd)`, где `t ≤ ⌊δk⌋+1`, худший случай `O(k²d)`. | `O(kd)` рабочего буфера, `O(tk)` на запись диагностик попытки. |
| CC и очередь | `O(M²d)` на первичные сравнения. Одно обновление требует `O(Md)` для сходств. Операции с множествами зависят от их размера, работа с очередью добавляет `O(log q)` на запись. | `O(Md+q)` сверх множеств memberships и аудита. |
| Вложенность | Сравниваются принятые группы, имеющие общих участников с заменяемыми. Верхняя оценка на операцию `O(Mk_max)` при ограниченном числе родителей. После merge дополнительно проверяются версии отложенных пар. | Инвертированный индекс линейного размера по числу memberships. |
| Append | `O(d)` на pre-EC и обновление сумм. После pre-EC полная проверка стоит `O(kd)` на кандидата плюс вложенность. Сквозной прогон рассматривает до `UM` пар сущность–концепт. | `O(kd)` на пробное обновление одного концепта. |

Размер файлов журнала зависит от числа попыток, размеров групп и раундов. Формирование сводной статистики отдельно считает строгие включения по всему каталогу. Полный CC может быть основным ограничением на больших каталогах с большим числом кандидатов.

Из корня репозитория с Python 3.11. Для локальной подготовки окружения доступны уже существующие extras `test` и `relex`. Dry-run использует замороженные входы Stage 3A.5.11 и векторы, окна и манифест Stage 3A.5.12. Для независимой сверки также нужны сохранённые `name_scores.npy` и `S1_scores.npy`.

```powershell
uv run --no-sync python -m pytest tests/test_shared_concepts_v2.py tests/test_contextual_shared_concepts.py tests/test_semantic_concepts.py tests/test_build_corpus_graph.py -q
uv run --no-sync python scripts/sweep_shared_concepts_v2.py --configurations config/shared_concepts_v2_sweep_smoke.json --run-id corpus100-shared-concepts-v2 --checkpoint-every 500
uv run --no-sync python scripts/verify_shared_concepts_v2.py artifacts/shared_concepts_v2/sweeps/corpus100-shared-concepts-v2/dry_run
```

Для возобновления повторяется та же команда с тем же `--run-id`, входом, конфигурациями и числом потоков. Чекпойнт EE восстанавливается целиком, очередь merge продолжает работу с последнего атомарно сохранённого состояния. Для незавершённой фазы до первой записи очереди повторяется подготовка сравнения CC. Завершённый результат переиспользуется после проверки контрольных сумм. В каталоге конкретной конфигурации находятся `ee.json`, `checkpoint.json`, `memberships.json`, `catalog.json`. Агрегат списка хранится в `results.json`.

Одиночный Corpus100 и независимая инкрементальная работа используют отдельные входы. Для нового независимого каталога можно опустить оба входных файла; полученное пустое поколение подходит как `--base`. Для профилей вместо чекпойнта ER используется `--profiles` с теми же `--documents` и `--model`.

```powershell
uv run --no-sync python scripts/run_shared_concepts_v2.py --corpus100 --config config/shared_concepts_v2_dry_run.json --run-id corpus100-local-check
uv run --no-sync python scripts/run_shared_concepts_v2.py --config config/shared_concepts_v2_dry_run.json --namespace example --run-id initial --resolution path/to/entity_resolution/corpus.json --documents path/to/initial.jsonl --model ../embedding-models/intfloat__e5-small-v2
uv run --no-sync python scripts/run_shared_concepts_v2.py --config config/shared_concepts_v2_dry_run.json --namespace example --run-id next --base initial --resolution path/to/delta/entity_resolution/corpus.json --documents path/to/delta.jsonl --model ../embedding-models/intfloat__e5-small-v2
```

## 6. Границы и готовность следующего эксперимента

- Раннер готов принять согласованный список значений пяти параметров. Проверен единственный набор. Полномасштабный перебор ожидает отдельной конфигурации.
- Практический порядок совпадающих значений Жаккара зависит от стабильных ID, в формировании которых участвуют конфигурация и namespace. Для повтора конкретного каталога используются тот же run ID и порядок обработки. Для сравнения параметров это часть зафиксированного рецепта. Смена namespace при тех же численных порогах может дать другой каталог.
- Для профилей с несколькими документами и изменения старых ревизий или ER-профилей требуется согласованная политика новой generation. Текущий CLI принимает append при неизменных старых профилях и совместимом рецепте. Production-публикация в MAIN/Neo4j остаётся отдельным инфраструктурным этапом. Corpus100 изолирован от независимых каталогов.
- Результаты характеризуют охват и поведение алгоритма на одном замороженном корпусе. Подтверждение семантической корректности, drift, эффекта последовательных исключений и downstream retrieval требует отдельной разметки и эксперимента. Precision, Recall и F1 в этом прогоне не рассчитывались.
