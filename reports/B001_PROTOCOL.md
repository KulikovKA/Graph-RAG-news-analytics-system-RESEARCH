# B-001 protocol — frozen before DEV inference and evaluation

Architecture B is an exploratory comparison on the 12 previously studied DEV documents, never a final independent test. The exact DEV allowlist and immutable hashes are inherited from `contracts/dev_manifest.json`. Source-only extraction is a separate process from offline evaluation. Neither CALIBRATION nor HOLDOUT is opened. No fine-tuning, training, fitting, Gold prompt selection or Gold examples in the prompt. The frozen ontology remains unchanged; inference sees only its hash-checked normative projection.

The model is the same local `qwen3.5:4b-q4_K_M` as the original architecture-A audit. Its manifest digest, all blob hashes, Ollama version, CPU settings and deterministic decoding are fixed in `config/b001.json` and `contracts/b001_model.json`. The prompt and JSON schema are in `config/b001_prompt.txt` and `contracts/b001_llm.schema.json`. No NLI gate is used. No external candidate inventory limits recall.

Each source chunk is split without rewriting Unicode into sentence-aware windows of up to three sentences and 1800 characters, one-sentence overlap. An exceptionally long sentence remains whole. Qwen gets the sentence IDs and exact text and produces typed mentions, indexed directed claims, evidence sentence IDs, polarity, modality, qualifier anchors and explicit abstentions. Occurrence ordinal is required for repeated exact surfaces. A unique exact surface can be mapped even if its generated ordinal is incorrect; an ambiguous or missing surface is rejected, not guessed. Overlapping entity spans are retained. All offsets and identifiers are assigned by code, and every accepted assertion has hash-checked source evidence covering its endpoints. Exact evidence establishes provenance only; semantic support is **not independently verified**.

Domain/range, required qualifiers, explicit scope conflicts, and grounded evidence are checked deterministically. Chemical `NO` is not treated as English negation. Valid negative/proposed claims are retained. Unrecognized or unsupported qualifier attachments are preserved separately, with UNKNOWN/UNSUPPORTED status, and are not guessed. All qualifier completeness is UNKNOWN; the unchanged strict C qualified scorer therefore awards no qualified TP until completeness can be established. Exact same directed claim, polarity, modality and qualifier payload repeated by overlapping windows is deduplicated; differing scope/status remains distinct. Entity linking reuses conservative case-sensitive source-scoped C linking, with device instances kept separate.

Raw model responses including failed attempts are saved separately. Mappable raw proposals, structural decisions, accepted assertions, rejected proposals and unresolved items are retained distinctly. Raw metric with the shared C scorer is calculated for proposals with mappable typed endpoints and source evidence; an additional raw-all metric counts unaddressable proposals as FP. For comparable candidate recall, the unchanged C single-sentence candidate generator is applied to B's predicted entities as an evaluation diagnostic; the full B window pairs are saved separately and never prune extraction. The C evaluator uses exact Unicode spans and kind, directed relations, and multiset matching. It cannot determine scientific truth or adjudicate missing Gold relations. D024 has incomplete relation annotation: unmatched predictions are not necessarily false.

Extraction uses a Python audit hook blocking label paths, original ontology examples, closed split paths, fitted RE imports and non-loopback networking. Only `127.0.0.1:11434` may be contacted. A source manifest checks all 12 inputs and the runtime ontology before inference. The model, source and contracts are hashed; raw/prediction files are checked before evaluation. A monitor samples combined client + Ollama server and descendant RSS and CPU every 0.25 s; shared server activity can affect resource estimates. Wall time includes input verification, model checks, inference and writing individual predictions, but excludes evaluator and final manifest writing. Tokens and calls come from the Ollama response, including retries; JSON failures, retries and request failures are counted. Failed or truncated generation fails the run after one identical retry instead of silently emitting an empty result.

Reproduction from repository root (Python 3.11 with dependencies from `uv.lock` and Ollama 0.35.0 with the pinned model installed):

```powershell
uv sync --frozen --extra test
uv run --no-sync cgraph fetch-dev
uv run --no-sync python -m bgraph.cli extract --output artifacts/b001/dev
uv run --no-sync python -m bgraph.cli evaluate --predictions artifacts/b001/dev --output reports/b001/metrics.json
uv run --no-sync python -m pytest -q
```

`fetch-dev` fetches only the allowlisted DEV snapshot and the 12 DEV Gold files; the B extraction process cannot open the latter. The existing local snapshot can instead be imported through the documented C `import-dev` command. Use a new, empty output directory. Full source texts, raw outputs, Gold and model blobs stay in ignored local data/artifacts; published metrics and short examples are derived only after all predictions are complete.
