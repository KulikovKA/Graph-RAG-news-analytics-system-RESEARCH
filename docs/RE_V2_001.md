# RE-V2-001 — два подграфа на исходном E3

Для актуального сценария **четырёх экспериментов, по две копии модели в каждом**
см. [RE_V2_001_FOUR_RUNS.md](RE_V2_001_FOUR_RUNS.md). Ниже описан первоначальный
общий entrypoint для двух E3-подграфов.

Единый entrypoint: `scripts/build_relex_graphs.py`. Нужны существующие `.venv`,
локальные веса `artifacts/models/gliner-relex-{base,large}-v1.0` и Neo4j старого
проекта `C:\Users\Kirill\Desktop\Graph-based RAG for article analysis`.
Дополнительные зависимости: `pip install -e ".[relex]"`.

Подключение задаётся переменными `NEO4J_URI` (по умолчанию
`bolt://127.0.0.1:17687`), `NEO4J_USER` (по умолчанию `neo4j`),
`NEO4J_PASSWORD` (обязательно), `NEO4J_DATABASE` (по умолчанию `neo4j`).
Можно прочитать только переменные `NEO4J_*` из существующего файла через
`--neo4j-env`. Пароль не попадает в код, конфигурацию эксперимента или отчёты.

При проверке этой локальной установки сервер отклонил пароль из текущего `.env`
старого проекта и принял исходный пароль по умолчанию, указанный в его
`compose.yaml`. `.env`, конфигурация контейнера и пароль сервера не изменялись.
Для запуска задайте действующие учётные данные в окружении PowerShell:

```powershell
$neo4jCredential = Get-Credential -UserName 'neo4j' -Message 'Existing Neo4j credentials'
$env:NEO4J_USER = $neo4jCredential.UserName
$env:NEO4J_PASSWORD = $neo4jCredential.GetNetworkCredential().Password
$env:NEO4J_URI = 'bolt://127.0.0.1:17687'
```

```powershell
# Если контейнеры остановлены: запуск существующих контейнеров, без создания новых.
docker start article-analysis-neo4j-1 article-analysis-neo4j-bolt-proxy-1 article-analysis-neo4j-browser-proxy-1

# Smoke test, обе модели одновременно, два документа, затем проверка импорта.
.\.venv\Scripts\python.exe scripts\build_relex_graphs.py --limit 2 --output reports/re_v2/relex_comparison/smoke --resume

# Первоначальный полный запуск: Base + Large, по 4 CPU-потока на процесс.
.\.venv\Scripts\python.exe scripts\build_relex_graphs.py

# Продолжить прерванный запуск или повторить идемпотентный импорт без инференса.
.\.venv\Scripts\python.exe scripts\build_relex_graphs.py --resume
```

Если переменные уже заданы, достаточно
`.\.venv\Scripts\python.exe scripts\build_relex_graphs.py`.

С `--workers-per-model 2 --threads 2` создаются четыре процесса: две копии Base и две копии Large.
Внутри каждой пары документы делятся на непересекающиеся части (для 30 документов
по 15 на worker). Каждый документ обрабатывается ровно один раз каждой моделью.
Каждый активный worker загружает одну копию своей модели один раз; всего в RAM
до четырёх копий. Результат по-прежнему состоит из двух подграфов.
Это параллелизм обработки документов, сущности по-прежнему берутся из E3.

Настройки можно задать явно:

```powershell
.\.venv\Scripts\python.exe scripts\build_relex_graphs.py --workers-per-model 2 --threads 2
```

`--threads` задаёт число CPU-потоков **на один worker**. Для прежнего режима
двух процессов: `--workers-per-model 1 --threads 4`. Изменение числа workers
совместимо с существующими checkpoints при `--resume`.
Фактическое ускорение нового режима пока не измерялось: эксперимент запускает пользователь.

## Исходные данные и адаптер API

Читаются исключительно `research_run2/input_abstracts.jsonl` и
`research_run2/E3/mentions_035.jsonl`: 30 документов, 1327 записей, 1211 уникальных
spans. Несколько исходных типов одного span сохраняются в `entity_types` и
`source_mentions_json`, включая исходные confidence, normalized_form, mention_id,
offsets и provenance. Один `RELEXEntity` соответствует document/start/end.
Между статьями сущности не объединяются.

Установленная GLiNER 0.2.26 принимает `input_spans` в
`UniEncoderTokenRelexGLiNER.inference`, но не передаёт вычисленные spans в forward.
Base использует `token_level`, Large — `markerV0`; Large дополнительно отбирает
spans по NER scores и ожидает полную сетку `L*max_width` даже для готовых spans.
Адаптер вызывает их существующие обученные encoder, RNN (если есть),
`project_start`/`project_end`/`out_project`, построение всех направленных пар и
`pair_rep_layer`. Это те же вычисления relation head, с заданным набором E3
вместо NER selection. Для markerV0 обходится только reshape полной сетки;
упоминания длиннее 12 слов тоже сохраняются. Веса и код GLiNER не изменяются.
`rel_idx` декодируется непосредственно в исходный порядок E3. Исходные NER
типы не переопределяются. Точные word-spans сохраняются в audit каждого окна.
Фактические сигнатуры и исходник `represent_spans` сохраняются в `*.api.json`.

Ровно 20 кодов берутся из Ontology v2, английские предикаты и обратное соответствие
сохранены в конфигурации. Отношения читаются от head к tail.
Порог по умолчанию 0.7; обе модели используют одинаковые окна, рассчитанные по
обоим локальным токенизаторам с учётом полного entity/relation prompt.
Лимит 512 subword-токенов, перекрытие 25%; ни одна граница не разрезает E3-span.
Реальная длина входа проверяется повторно после collator.
Связи между сущностями, которые никогда не попали в общее окно, не извлекаются.

Процессы `spawn` загружают по одной копии модели и ждут друг друга на барьере
перед инференсом. У каждого отдельный progress bar и лог `base.worker1.log`,
`base.worker2.log`, `large.worker1.log`, `large.worker2.log`. Workers с полностью
готовой частью корпуса при `--resume` не загружают модель.
Атомарные checkpoints создаются на документ. `--resume` проверяет
fingerprint входов, онтологии, весов и настроек, пропуская готовые документы.
При недоступной авторизации можно отдельно выполнить `--inference-only`;
отчёт явно помечает графы как `NOT_IMPORTED`. После исправления подключения
`--resume` импортирует сохранённые результаты без повторного инференса.
После завершения инференса выполняется идемпотентный импорт по детерминированным
ключам и проверка числа документов, сущностей, mentions и directed relations.

## Neo4j и просмотр

Используется старый Neo4j Community из `compose.yaml` и существующие прокси из
`compose.neo4j-browser.yaml`. Новые контейнеры и базы не создаются.
Выделенные labels `RELEXDocument`/`RELEXEntity` и relationships
`RELEX_MENTIONS`/`RELEX_REL` не пересекаются со старой онтологией.
Каждый ключ содержит namespace; каждый узел и ребро имеют `namespace`.
Удалений нет. При несовместимом fingerprint в целевом namespace импорт останавливается.

Открыть <http://127.0.0.1:17474>, подключиться к `bolt://127.0.0.1:17687`
с существующими учётными данными. В Browser может потребоваться увеличить
Graph visualization node limit до 1500 для полного отображения одного подграфа.

```cypher
MATCH (e:RELEXEntity {namespace: 'relex_base'})
OPTIONAL MATCH (e)-[r:RELEX_REL {namespace: 'relex_base'}]->(t:RELEXEntity {namespace: 'relex_base'})
RETURN e,r,t;
```

```cypher
MATCH (e:RELEXEntity {namespace: 'relex_large'})
OPTIONAL MATCH (e)-[r:RELEX_REL {namespace: 'relex_large'}]->(t:RELEXEntity {namespace: 'relex_large'})
RETURN e,r,t;
```

Готовые `base.cypher`/`large.cypher` также включают запросы к документам и их
упоминаниям. Исходные данные старого проекта не изменяются.

## Отчёт

Результаты: `reports/re_v2/relex_comparison/`. `*.predictions.jsonl` содержат
документы с полными исходными предсказаниями по окнам, `*.relations.jsonl` —
уникальные направленные тройки. Максимальный confidence выбирается по всем
окнам; все evidence сохраняются. `*_only.jsonl` показывают различия моделей.
Есть `metrics.csv`, `per_document.csv`, `relation_distribution.csv` (все 20 типов),
`confidence_distribution.csv`, `comparison.json`, `report.md`, логи, конфигурация,
общий план окон и исходные сущности.

Ontology v2 пока не задаёт формальную матрицу domain/range. Поэтому формальная
доля её нарушений не вычисляется. Отдельные эвристические review hints выводятся
из определений HAS_ATTRIBUTE/HAS_RESULT/USED_FOR/PERFORMS/EVALUATED_ON/MEASURES/
EXPLAINS и явно обозначены как неутверждённые подсказки, а не доказанные ошибки.
Ни один такой кандидат не удаляется. Gold-разметка не используется.
Peak RAM измеряется семплированием RSS родителя и всех workers, отдельно от Docker.
Для каждой модели суммируется RSS её workers в один момент времени; отдельно
сохраняются пики каждого процесса. Model wall time — максимум времени workers;
сумма времени обработки документов остаётся отдельной метрикой.

Проверка: `.\.venv\Scripts\python.exe -m pytest tests/test_build_relex_graphs.py -q`.

## Состояние подготовки

Проверены обе модели на двух документах: по 42 уникальных E3-span, Base —
13 троек, Large — 5; 4 тройки общие. Smoke-подграфы импортированы и проверены:
по 2 документа, 42 сущности и 42 RELEX_MENTIONS; пересечений namespace нет.
11 автоматических тестов прошли.

По последующему указанию пользователя полный запуск остановлен во время загрузки
моделей, до инференса и импорта 30 документов. Дальнейший запуск выполняет
пользователь. Подготовленные конфигурация и окна сохранены; запуск без `--resume`
разрешён, если ещё нет готовых checkpoints. Данные smoke test остаются в Neo4j
и будут идемпотентно переиспользованы полным запуском с теми же настройками.
