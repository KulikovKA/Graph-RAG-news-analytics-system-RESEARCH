# Stage 3A.5.12 · Contextual Shared Concepts

Проверяем, сокращает ли независимый порог по локальному контексту число
междокументных пар при фиксированном пороге по названию, сохраняя кандидатов
по всем пяти темам и для повторных научных терминов из диагностики.
Предполагаем, что длинные окна могут повышать сходство разных сущностей из
близких по теме документов. Сравниваем девять окон, пять порогов по каждой
оси, варианты с защитными проверками и замороженный Hybrid C 0.830.
Пригодность кандидатов к общему концепту проверяется будущей ручной разметкой.

Входы — [Corpus100](../../reports/retrieval/benchmark_3a5_11/corpus100/SPEC.md)
из заморозки `750d03a` с лицензиями CC BY 4.0 / CC0 1.0, checkpoints
[графа](STAGE_3A5_11_CORPUS100_GRAPH.md) и
[диагностика](../../reports/retrieval/benchmark_3a5_11/shared_concepts_diagnostics/REPORT.md).
Corpus100 — целевой описательный срез без Gold, DEV/CAL/HOLD здесь отсутствуют.
Существующие split и результаты других этапов изолированы. Используем
канонические ID и исходные spans, включая члены 13 объединений ER. Параметры
E5 наследуем из 3A.5.11, веса и tokenizer закрепляем хешами, seed 42, CPU FP32,
одна сессия, batch 8, 512 токенов. Сетка каждого порога 0.75–0.95, шаг 0.05.

Окна S0–S3 охватывают предложения, пересекающие span, с 0–3 соседями.
Окна W8–W128 берут 8, 16, 32, 64 или 128 слов с каждой стороны. Слово —
максимальная последовательность непробельных Unicode-символов. Границы
предложений определяются пунктуацией с орфографическими исключениями для
сокращений и инициалов. Фрагменты сохраняются как исходные подстроки.
При превышении лимита токенов сокращаем контекст вокруг span, сохраняя
название, префикс и целое упоминание. Одинаковые итоговые контексты сущности
имеют один вес и все исходные provenance. Названия и окна кодируются
независимо, индивидуальные векторы L2-нормализованы, их среднее сохраняется
без повторной нормализации.

Берём верхний треугольник без диагонали и пары разных документов. Cosine
вычисляется в float64 по временно нормализованным векторам. Условия
`name >= t_name` и `context >= t_context` применяются совместно, без Top-K.
Защита проверяет provenance, метку RESULT, совместимость замороженных
типов и явно конфликтующие раскрытия. Уровень абстракции отдельно
проверяется вручную. Считаем оба набора кандидатов, исключения в порядке
правил, уникальные сущности, документы и пары документов. Знаменатели
покрытия — все сущности и документы среза или темы. Межтематическое
распределение — по неориентированной паре тем. Распределения cosine считаются
на всех междокументных парах с популяционным SD и линейными квантилями.
Представляем описательные результаты без оценок качества и интервалов.
Для Hybrid C различаем кандидатов, решения и итоговые memberships.

Бюджет — один локальный проход по уникальным строкам E5, до девяти блочных
проходов cosine контекста, один проход cosine названий, до 6 часов и 4 GiB
RSS для этапа. API inference, обучение и платные токены не используются.
Прерываемся при ошибке provenance, несовместимом checkpoint или исчерпании
ресурсов. SQLite сохраняет готовые batches, атомарные checkpoints хранят
завершённые окна и хеши. Новый выход `artifacts/benchmark_3a5_12` изолирован.
Возобновление сверяет входы, рецепт, код и выполненные checkpoints.
Публикуем агрегаты, seed, хеши и диагностические строки. Полная слепая
выборка с исходными evidence находится в локальных артефактах. В MLflow
передаются агрегаты в существующий `data_expansion`.

Приёмка — 100 документов, 4 506 ID, 10 149 765 пар, 10 042 851
междокументная пара, 225 строк sweep, девять проверенных матриц окон,
20 перенесённых диагностических строк и воспроизводимая blind-выборка.
Отдельные тесты проверяют geometry окон и offsets, truncation, среднее,
cosine, пересечение порогов, монотонность, исключения и resume. На корпусе
сверяем числа, доказательства, хеши входов и повторную сборку результатов.
Риск — тематическая близость документов, полисемия, ошибки NER-типизации
и смещение диагностических примеров. Без пользовательских меток данные
используются для планирования разметки. Запись в Neo4j, повтор NER/RE/ER,
изменение Retrieval C и выпуск memberships за рамками этапа.
